## Why a seam

The item says "through a fake at the `store:` seam", but that `store:` is an
`HKHealthStore`. An `HKSampleQuery` result handler cannot be driven from a
test, and a unit test cannot grant Health read access. So:

1. **Pure conversion functions** in `PhaseTraining/Health/PhysiologyReader.swift`:
   - `static func readings(_ samples: [HKQuantitySample], unit: HKUnit) -> [PhysiologyReading]`
   - `static func sleepSamples(_ samples: [HKCategorySample]) -> [PhysiologySleepSample]`
   The two private query helpers (`quantities`, `sleepSamples(_:predicate:store:)`)
   call these inside their result handlers. Same output as today.
2. **Source protocol**, same file:
   ```swift
   protocol PhysiologySource {
       func requestAuthorization() async throws -> Bool
       func samples(from start: Date, to end: Date) async throws -> PhysiologyRawSamples
   }
   struct HealthKitPhysiologySource: PhysiologySource { /* forwards to PhysiologyReader */ }
   ```
   `PhysiologyCapture.connect(store:source:)` and
   `refreshIfEnabled(store:source:now:force:)` take
   `source: PhysiologySource = HealthKitPhysiologySource()`. Callers at
   `PhaseTrainingApp.swift:854` and `PhysiologyCaptureSection.swift:79` stay
   unchanged (defaults). Keep the `inFlight` guard and the post-await
   `store.isEnabled` re-check exactly as they are.

## Tests

Add to `PhaseTrainingTests/PhysiologyNightTests.swift` (existing file, no
xcodegen run). Use a fresh `UserDefaults(suiteName:)` per test and a fake
`PhysiologySource` that records calls.

Conversion (construct real `HKQuantitySample` / `HKCategorySample`):
- HRV given in seconds (0.045 s) reads back as 45 ms with the ms unit.
- Resting HR given as count/s converts to count/min (1 /s → 60).
- Sleep: each asleep stage maps, inBed and awake keep their stage, an
  unknown raw value (e.g. 99) is dropped; start/end carried through.

Capture:
- connect, source returns false → `.unavailable`, capture stays off, no read.
- connect, auth throws a `LocalizedError` → `.failed(<its description>)`, off.
- connect success → `.connected(nights: n)` with n from the fake's samples,
  `isEnabled` true, `lastRefresh == now`-ish (set), nights saved.
- refresh while disabled → source never called.
- refresh within `minRefreshInterval` of `lastRefresh` → skipped;
  `force: true` reads anyway; after the interval reads.
- source throws on read → stored nights and `lastRefresh` unchanged.
- fake calls `store.stopAndDelete()` inside `samples` → nothing written back
  (nights empty, lastRefresh nil).

Coach balance, in `PhaseTrainingTests/CoachContextTests.swift`, on
`CoachContext.muscleBalanceSection` (`CoachContext+MovementBlocks.swift:78`):
- no sessions → nil; sessions outside 4 weeks → nil.
- header line, at most 5 rows, top row "100% of top".
- a group under one third of the top gets " · underdone"; one at or above
  one third does not.
Build sessions the way existing CoachContextTests / MuscleVolume tests do;
read `MuscleVolume.rows` to pick exercise names that resolve to muscles.
