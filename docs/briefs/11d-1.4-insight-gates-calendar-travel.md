## Design

### InsightGenerator

Add an internal pure gate and have `runIfDue` use it:

```swift
enum Gate: Equatable { case coachUnavailable, noConsent, notPro, inFlight, alreadyToday, noSignal, due }

static func gate(memory: TrainingMemory, sessions: [SavedSession], consentGranted: Bool,
                 now: Date, available: Bool = CoachEntitlement.coachAvailable,
                 pro: Bool = CoachEntitlement.proSatisfied(),
                 inFlight: Bool = InsightGenerator.inFlight) -> Gate
```

Order matches today's guards exactly: available, consent, pro, inFlight, alreadyToday, signal. `runIfDue` becomes `guard gate(memory: memoryStore.memory, sessions: sessionStore.savedSessions, consentGranted: consentGranted, now: now) == .due else { return }` and keeps the snapshot and network path unchanged. `hasInsightForToday` and `hasSignal` stay private. Keep the existing comment about coachAvailable going first (move it onto `gate`). If a default argument cannot read the private `inFlight`, make the parameter non-defaulted and pass `inFlight` from `runIfDue`.

### CalendarTravelReader

1. Add `status: EKAuthorizationStatus = EKEventStore.authorizationStatus(for: .event)` to `findTravel` and switch on it.

Extract the window math into `static func readWindow(weekStart: Date, calendar: Calendar) -> (start: Date, from: Date, to: Date)?` (start of day of weekStart; from = start - 2 days; to = start + 7 days + 2 days; nil when the +7 add fails, matching today's `.found([])` return). `findTravel` uses it.

## Tests

`InsightGeneratorGateTests` (`@MainActor`): one case per gate result, each passing the explicit `available`, `pro`, `inFlight` values:
- available false gives `.coachUnavailable` even with consent and signal
- consent false gives `.noConsent`
- pro false gives `.notPro`
- inFlight true gives `.inFlight`
- an insight dated today gives `.alreadyToday`; one dated yesterday does not block
- no feedback, no pain soreness, no session in 3 days gives `.noSignal`; soreness without pain is not a signal; a session 4 days ago is not a signal
- each signal alone (feedback 6 days ago, pain soreness 6 days ago, session 2 days ago) gives `.due`

Build `TrainingMemory`, `SavedSession`, feedback and soreness values the way existing tests do (grep `PhaseTrainingTests/` for their initializers). No network.

`CalendarTravelReaderTests`:
- `.denied`, `.restricted`, `.writeOnly` each return `.denied` (call `findTravel(weekStart:calendar:store:status:)`)

- `readWindow` across the March 2026 DST change (weekStart 2026-03-06) still lands on midnights
