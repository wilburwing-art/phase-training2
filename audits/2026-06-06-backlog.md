## Tier 0 — Ship blockers / correctness blast radius

- [x] **LLM per-day refinement is blind to sport load.** `refineSingleDay()`
  builds its `GeneratorContext.from(...)` WITHOUT `sportLogs`, while the
  top-level `refineCurrentPlanWithLLM()` context includes them — so
  `recentHardSportDays` is always 0 per-day and refinement can push intensity
  the user's weekly sport load doesn't warrant. Thread `sportLogs` through the
  `refineSingleDay` signature (match the sessions/profile/snapshot pattern —
  also resolves the closure-capture smell flagged at the same site).
  `PhaseTraining/Data/PlanStore+LLMRefinement.swift:214` (decl :154, call :130).
  **Fixed `18737fa`** — sportLogs threaded through the signature and per-day context.
- [x] **Backup restore: UserDefaults half is not atomic.** SQLite restore got
  capture→populate→verify→rollback in `f6e0326`, but the four sequential
  `try encodeAndWrite` UserDefaults writes (pt_training_memory,
  pt_active_session, pt_week_plan, pt_week_overrides) have no prior-state
  capture and no rollback — a mid-sequence throw leaves mixed old/new state.
  Capture the four prior values first; restore them on any throw.
  `PhaseTraining/Data/BackupManager.swift:164-172`. **Fixed `66465f7`** — all 7
  touched keys captured + rolled back on throw; new test injects a poisoned
  ActiveSession encode mid-sequence and asserts both stores roll back.

- [x] **"PERSONALIZED BY COACH" badge ignores consent/entitlement.**

  edit protection (§8) — reset state, don't restructure the guard.

  imperial/metric swaps the rendered TextFields but `@FocusState` retains the

  `PhaseTraining/Screens/Onboarding/OnboardingAboutScreen.swift:217`.
  **Fixed `c547d89`.**
- [x] **Reminders toggle lies on failure.** `toggleReminders()` flips
  `remindersOn` before `WeeklyReminderScheduler.enable()` resolves; if enable

  **Half false-positive, half fixed `0ff2f65`** — the revert was already correct
  (remindersPending pattern, since 1d03936); the real gap was the silent

- [x] ~~Replace-event alert can show stale incumbent text.~~ VERIFY FIRST
  (`ios-audit-finding-false-positives` — the skeptic's "alert stays visible"
  mechanism is suspect: SwiftUI alerts auto-dismiss on any button tap). The

  before coding; if real, snapshot the incumbent title into a `@State` when the
