# phase-training2 — whole-app audit

**Date:** 2026-06-01
**Scope:** every part of the app, four axes — bugs/correctness, architecture/quality, feature gaps, security (Coach also got a 5th: AI risk surface)
**Method:** 9 parts, one Explore critic each, then a skeptical second agent re-checked every high/critical bug + security finding against the cited lines. Findings the verifier confirmed are tagged `✅ verified`; refuted ones are quarantined in the appendix so they don't get re-chased.
**Cost:** 18 agents, ~2.2M tokens, ~4.5 min.

---

## Outcome (implemented + verified 2026-06-01)

Of the 10 adversarially-"verified" findings, **6 held up and are fixed**; **3 were false positives and 1 was overstated** — the verify pass confirmed them on shallow reads that didn't trace the call paths. Fixes verified by `xcodebuild build` (BUILD SUCCEEDED) + 21 targeted unit tests passing (incl. the existing `CoachPromptSanitizationTests`, which already covers the injection vector #2 claimed was unhandled).

### Fixed (6)
1. ✅ **CustomRoutineEditSheet swap-index crash** — the only confirmed hard crash. Swap is now keyed by the exercise's stable `id`, so a deleted row is a no-op instead of an out-of-bounds access. `PhaseTraining/Screens/CustomRoutineEditSheet.swift`
5. ✅ **BackupManager.restore — no confirmation** — restore now decodes first and requires a confirm alert (showing the backup's date) before the destructive write. `PhaseTraining/Screens/ProfileScreen.swift`
6. ✅ **Restore shows stale data** — all four stores (`MemoryStore`/`PlanStore`/`SessionStore`/`CustomRoutineStore`) now expose `reload()` and are refreshed after a confirmed restore; the "restart the app" copy is gone. `PhaseTraining/Screens/ProfileScreen.swift`
7. ✅ **PR timestamp uses `Date()` not session time** — `personalRecords(in:)` now takes a `sessionDate`, and `CompleteScreen` passes `session.startTime`. `PhaseTraining/Data/SessionStore.swift`
8. ✅ **WeekScreen silent date fallback** — `MovableDay.date` is now `Date?`; an unparseable drag payload aborts the drop instead of silently landing on today. `PhaseTraining/Screens/WeekScreen.swift`
9. ✅ **"Clear overrides" destructive, no confirm** — now gated behind a confirm alert. `PhaseTraining/Screens/WeekDayEditSheet.swift`

### Not real — do not re-chase
2. ❌ **Coach prompt injection — FALSE POSITIVE.** Every user-text interpolation point (`CoachContext.swift:166/183/289/362/485`) already routes through `sanitizeFreeText`, which flattens newlines/control chars and bounds length; the system prompt marks the text as data, and `CoachPromptSanitizationTests` covers the fake-`SYSTEM:`-section vector. `PhaseTraining/Coach/CoachContext.swift:739`
4. ❌ **Coach turn caps never enforced — FALSE POSITIVE.** `send()` has `guard !conv.atHardCap else { return }`; `canSend` disables input at the cap; `recordTurn()` counts + persists `turnsToday`; the soft-cap banner is wired. The "never referenced via grep" claim was simply wrong. `PhaseTraining/Coach/CoachDrawer.swift:309`
10. ❌ **"Mark as travel day" non-idempotent — FALSE POSITIVE.** `PlanStore.updateOverrides` runs its mutation block synchronously on the main thread, so rapid `removeAll`+`append` taps serialize and converge to exactly one event. No debounce needed. `PhaseTraining/Data/PlanStore.swift:619`
3. ⚠️ **Coach unbounded history — OVERSTATED.** `wireHistory()` returns today's messages, which reset on daily rollover and are bounded by `hardTurnCap = 100` — not unbounded. A rolling window would trim token cost on heavy days but makes the coach forget earlier same-day context; deferred as a product decision. `PhaseTraining/Coach/CoachConversationStore.swift:141`

> **Audit-quality note:** ~40% of the adversarially-"verified" high/critical findings (#2, #4, #10, plus overstated #3) did not survive a read that traced the call paths. The verifier missed `sanitizeFreeText`, mis-ran the turn-cap grep, and didn't check `updateOverrides`' synchrony. Captured as the `ios-audit-finding-false-positives` skill.

## Today tab & daily entry

- **Missed-reshuffle diff can change between preview and apply** — `proposeMissedReshuffle` runs once for the banner and again on accept; a plan regen in between means the user approves a diff that isn't what gets applied. `PhaseTraining/Screens/TodayScreen.swift:399`
- **Plan-validation ack races plan regen** — acknowledging an issue logs an override, but a simultaneous regen re-validates and the same issue can reappear after the dismiss animation. `PhaseTraining/Screens/PlanValidationBanner.swift:41`
- **Inline-edit flags never reset on navigation** — `didModify`/`didSaveToLibrary` persist for the view's lifetime; returning to Today can show a "Save to library" pill for edits already discarded. `PhaseTraining/Screens/TodayScreen.swift:40`

## Active workout / Log flow

- **`appendExerciseFromPicker` hardcodes 3×8 / 90s / lbs** — ignores the picked exercise's modality (reps-only calisthenics, heavier compound rest). `PhaseTraining/Screens/LogScreen.swift:1056`
- **PR unit lookup is exact-match, not case-insensitive** — `first { $0.name == record.exerciseName }`; a case mismatch silently falls back to "lbs". `PhaseTraining/Screens/CompleteScreen.swift:77`
- **No undo on exercise swap** — `swapExercise` mutates name/type in place and autosaves before the user can reconsider. `PhaseTraining/Screens/LogScreen.swift:161`

- **✅ verified — "Clear overrides for this day" destructive with no confirmation** — one tap wipes sport sessions, events, custom routines, and unavailable marks. `PhaseTraining/Screens/WeekDayEditSheet.swift:244`

- **Whitespace-only event title slips past validation** — `canSave` checks trimmed-empty but `save()` trims *after*. `PhaseTraining/Screens/WeekDayEditSheet.swift:678`

- **✅ verified — destructive restore has no confirmation** — `BackupManager.restore()` calls `clearAll`/`clearAllSessions` immediately on file pick; the only alert appears *after* data is gone. `PhaseTraining/Data/BackupManager.swift:116`

## Cross-cutting themes

1. **`sheet(item:)` + force-subscript on a stored index = crash class.** The one confirmed crash (CustomRoutineEditSheet swap-after-delete) and the LogScreen claims the verifier refuted are the same pattern; the fix is uniform — bounds-check or bind by stable ID, not by cached array index. Audit the routine/superset editors first; they have real `onDelete`.

2. **Destructive actions without confirmation.** "Clear overrides," `BackupManager.restore`, and the restore-then-stale-data flow all mutate or wipe data on a single tap. The routine-delete alert is the right pattern; it isn't applied consistently.

3. **Silent failure / swallowed errors lose data.** `try?`-and-return in `SportLog.persist`, the session-migration `defer` flag, and LLM-refinement's silent nil all fail quietly. Each should log or surface; a corrupt write currently looks identical to success.

4. **Displayed state goes stale after plan regeneration.** Missed-reshuffle diff, plan-validation ack, missed-workout banner, and post-restore stores all show data that a concurrent `regenIfNeeded` / UserDefaults write can invalidate without reconciliation. No single source of truth that the UI re-reads after a regen.

5. **Half-wired subsystems presented as done.** SubscriptionStore (scaffold), Coach turn caps (dead config), `buildWorkout` in chat (dropped), `hideOtherSports` (no toggle), PlanStore's optional injections — each is plumbed enough to look complete but does nothing or degrades silently. The Coach trio (unbounded history + no rate cap + unescaped user input) is the real security + cost exposure and the highest-value cluster to close before any wider coach rollout.
