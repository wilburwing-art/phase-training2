# Brief: 11e 1.2, sport picker from the catalog

Backlog item: `docs/PLAN-gap-backlog-2026-11e.md`, Phase 1, item 1.2.

## Problem

Onboarding (`PhaseTraining/Screens/Onboarding/OnboardingSportsScreen.swift:31`)
and the Profile sports editor (`PhaseTraining/Screens/SportsEditorSheet.swift:24`)
both show `Sport.catalog.filter { SportCatalog.isPlannable($0.slug) }`: a flat
chip cloud drawn from a hardcoded list of 35 (`TrainingMemory.swift:514`).
Since 1.1, many coach.db sports outside that list are plannable through a
family row (`SportProfile.familySlug`), and they cannot be picked. Content
phases 3 to 5 add more, and each would need a hand edit to the list.

## Design

1. `CoachDatabase` (`PhaseTraining/Data/CoachDatabase.swift`): add
   `func sportCategoryRows() -> [(slug: String, name: String, parentSlug: String?, sortOrder: Int)]`,
   every `sport_categories` row with its parent slug, ordered by
   `sort_order, name`. Same `withLock` / prepare / finalize pattern as
   `sportParentSlugs()` next to it.

2. New file `PhaseTraining/Data/SportPickerCatalog.swift`:
   - `struct SportPickerSection: Identifiable { let root: Sport; let sports: [Sport]; var id: String { root.slug } }`
   - `enum SportPickerCatalog`
     - `static let sections: [SportPickerSection]`, computed once (coach.db is
       read-only). Take every row from `sportCategoryRows()` whose slug passes
       `SportCatalog.isPlannable`. Group each under its depth-0 root: walk
       `parentSlug` up to a row with no parent. Use the `parent_id` chain here
       and ignore `SportProfile.familyOverride` (that maps programs; the
       picker groups by the catalog tree). Section order is the root's
       `sort_order`; sports within a section by `sort_order`, then name. A
       root that is itself plannable is listed first in its own section
       (general-fitness is its own one-sport section; snow-sports sits first
       in Snow Sports). A section with no plannable sport is dropped.
     - Display names: `Sport.catalog`'s name wins when the slug is there
       ("Brazilian Jiu-Jitsu", "Skiing / Snowboarding"); otherwise the coach.db
       name. The section header is the root's coach.db name, with the same
       override rule.
     - `static func sections(matching query: String) -> [SportPickerSection]`:
       trimmed, case- and diacritic-insensitive substring over each sport's
       display name and slug (hyphens read as spaces). A root-name match keeps
       the whole section. Empty query returns `sections`. Sections that end
       empty are dropped.
     - `static func sport(slug:) -> Sport?` for lookups below.

3. `Sport.resolve(slug:)` (`TrainingMemory.swift`): after the two catalog
   lookups and before the prettified synthetic fallback, look the slug up in
   `SportPickerCatalog` (or the coach.db rows) and return that name, so a
   picked `tennis-clay` decodes as its coach.db name. `Sport.catalog` itself
   stays (other callers use it: `WeekDayEventSheets`, `PhaseTrainingApp`
   seeding, previews). Update its doc comment: it is now the display-name
   override list and the source for those callers, and the pickers read
   `SportPickerCatalog`.

4. Both screens: replace the flat `WrappingFlow` with a search field and one
   labelled section per `SportPickerSection` (section label in the screen's
   existing label style: `OnboardingSectionLabel` in onboarding, `.micro`
   ink3 text in the sheet; chips in a `WrappingFlow` under each). Search field:
   look at `ExercisePickerSheet.swift` / `InjuryPickerSheet.swift` for the
   app's existing field styling and reuse it. Placeholder "Search sports".
   Accessibility identifier `sport-search`. Empty result shows one line,
   "No sport matches. More are added as programs land." Keep the chip
   identifiers exactly `onboarding-sport-<slug>` (UI tests depend on them).
   The section headers get `.accessibilityAddTraits(.isHeader)`.
   Everything else on both screens (primary pick rows, "keep at least one"
   copy, toggle logic) stays as is.

## Tests (new class `SportPickerCatalogTests`)

- Every sport in every section passes `SportCatalog.isPlannable`.
- Every plannable slug in `Sport.catalog` appears in some section (the
  old picker's set is a subset of the new one).
- `sections(matching: "fencing")` is empty (fencing's one routine is 20 min,
  under the 25-minute floor), and `SportCatalog.isPlannable("fencing")` is
  false. Comment that this flips when fencing gets routines.
- `sections(matching: "tennis")` contains `tennis`. `sections(matching: "TENNIS ")` gives the same.
- `bjj` shows as "Brazilian Jiu-Jitsu"; a plannable slug outside
  `Sport.catalog` shows its coach.db name. Pick one by measuring, not guessing.
- Section ids are unique and no slug appears twice across sections.
- `Sport.resolve(slug:)` on a coach.db slug outside `Sport.catalog` returns
  the coach.db name.
