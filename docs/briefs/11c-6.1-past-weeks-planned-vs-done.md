# Brief: 11c 6.1 Past weeks, planned versus done

Backlog item: `docs/PLAN-gap-backlog-2026-11c.md` 6.1. A week-by-week strip on
Progress from `PlanStore.pastPlans`, placed beside `sessionsCard`.

## Design (lead)

### Stale session ids in the snapshot

`WeekPlanSnapshot.actualSessionIDs` is frozen when the snapshot is taken
(`snapshotCurrentPlan`, called from regeneration and on promotion).
`captureRolloverIfNeeded` skips a week that already has a snapshot, so a week
snapshotted on Monday never picks up the sessions logged Tuesday to Sunday.
Calling `snapshot.completionRatio(in:)` directly would under-count. The strip
re-joins by date window instead: for each snapshot, take
`WeekPlanSnapshot.capture(snap.plan, sessions: allSessions, now: snap.capturedAt)`
and read the counts from that. This leaves the stored data and the existing
helpers untouched. The same bug in `PlanArc.isBuildWeek` is filed as a separate
backlog item. Leave PlanArc alone.

### Pure model, new file `PhaseTraining/Data/PastWeeksSummary.swift`

```swift
struct PastWeekRow: Hashable, Identifiable {
    let weekStart: Date
    let planned: Int      // plannedLiftDays + plannedSportDays
    let done: Int         // distinct calendar days with a session in the week window
    var id: Date { weekStart }
    var ratio: Double     // done / planned clamped to 0...1.5; 0 when planned == 0
}

enum PastWeeksSummary {
    /// Completed weeks only: weekStart < today's startOfTrainingWeek.
    /// Oldest first, at most `limit` (default 8, matches ProgressScreen.weeks).
    static func rows(snapshots: [WeekPlanSnapshot],
                     sessions: [SavedSession],
                     today: Date = Date(),
                     calendar: Calendar = .current,
                     limit: Int = 8) -> [PastWeekRow]
    /// One VoiceOver sentence, e.g. "8 weeks. Week of Nov 9: 3 of 4 done. ..."
    static func spoken(_ rows: [PastWeekRow]) -> String
}
```

Use `capture` and `completedSessionCount` from `PlanHistory.swift` for the counts.
Do not reimplement the day-collapse rule. A rest week (planned 0) still gets a row.

### UI, `PhaseTraining/Screens/Progress/ProgressScreen+StatCards.swift`

- Add `@EnvironmentObject var planStore: PlanStore` to `ProgressScreen`
  (`ProgressScreen.swift`). Check that every place `ProgressScreen` is built,
  previews included, has a `PlanStore` in its environment. Add one where it is
  missing (grep `ProgressScreen()`).
- `var pastWeeksCard: some View`, inserted directly after `sessionsCard` in
  `ProgressScreen.swift` `content`. Hidden (`EmptyView`) when `rows` is empty.
- `card(title: "PLANNED / DONE")`. One column per week, oldest left to newest
  right, the same visual weight as `sessionBar`. Each column has a bar track
  (`Color.elevated`) with a fill of `min(ratio, 1)` (`Color.accent` when
  done >= planned and planned > 0, else `Color.accentDim`) and a `done/planned`
  label under it in `.monoXS` `Color.ink3`. For a rest week the label is `rest`.
  Footer row in the `sessionsCard` style: "\(n)w ago" left, "last week" right.
- Accessibility: one element, label "Planned versus done", value
  `PastWeeksSummary.spoken(rows)`, `.accessibilityIdentifier("progress-past-weeks")`.
- Dynamic Type: labels must not truncate at accessibility sizes. Use
  `.minimumScaleFactor(0.7)` with `lineLimit(1)` on the per-column label. That
  label is a short number fraction.
- Use existing colors and fonts only. Add no new design tokens.
