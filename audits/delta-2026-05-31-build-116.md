## New findings (not in the build-110 audit)

- **N1 — The coach cost cap is not implemented.** ✓ `softTurnCap = 50` / `hardTurnCap = 100` are defined and read **nowhere else** (`CoachConfig.swift:33,37`). This contradicts the strategy doc, which states the 50/100 cap "exists to bound" worst-case COGS (`full-review-2026-05-26/08-strategy.md:50-52`). The 85%-margin economics rest on a guardrail that does not exist in code. **Pre-launch P0.**
- **N2 — Dangling FK in the catalog schema.** ✓ `explanation_templates.trigger_type_id REFERENCES adjustment_trigger_types(id)`, but `adjustment_trigger_types` is never created (`db/source/_schema.sql:171`); `build_db.py` silently skips it. The adjustment-explanation chain is dead.
- **N3 — Image licensing gap.** Fan-out (sqlite3) reported ~85 exercises in shipped `coach.db` with `image_url` but NULL `image_license`/`image_attribution`. Not re-verified here — confirm before App Store submission (copyright exposure on bundled imagery).
- **N4 — Coach prompt-injection + PII surface.** User free-text (feedback notes, dislikes, injury descriptions) flows unsanitized into the per-turn system prompt via `CoachContext.snapshot()` (`Coach/CoachContext.swift`, `Coach/CoachSystemPrompt.swift`). A free-text "ignore previous instructions" or an identifiable injury note goes verbatim to the API. Design risk.
- **N5 — Weekly Check-In loses state on Back.** Fan-out: `regenerateAndAdvance()` snapshots the preview plan but doesn't persist; Back discards it with no warning, and `Planner.generate` has no timeout/error state (infinite spinner). `Screens/WeeklyCheckIn/WeeklyCheckInFlow.swift:176,142-144`, `CheckInPreviewScreen.swift:37`. Not re-verified.

## Dependencies / coupling

- **External:** one SPM package — `MuscleMap` (pinned `exactVersion: 1.6.4`, MIT, zero-dep; `Project.yml:53`). Networking is raw `URLSession`, DB is raw SQLite C API. Low supply-chain surface. Risk: the hand-maintained slug→muscle bridge (`Components/BodyAnatomyView.swift`) silently drops unrecognized coach.db slugs.
- **Internal:** three high-fan-in stores — `MemoryStore` (36 files), `PlanStore` (34), `SessionStore` (34). `PlanStore` (1014 lines) is the orchestration god-object. `CoachDatabase.shared` is a non-injectable global hit from ~23 sites incl. `TrainingMemory.init(from:)` mid-decode → core logic can't be unit-tested without the bundled SQLite. Stores are cross-wired late in `RootTabView.task` (`App/RootTabView.swift:70-90`).
- **Build/data:** `coach.db` is reproducible from committed JSON via `scripts/db/build_db.py`. Python pipeline has no `pyproject.toml`/lockfile (per-script PEP-723 headers); `scripts/quality/` is one-off CLIs; `validate_coverage.py` is not wired to CI. Gateway token is baked into the IPA via the `CoachSecrets.swift` pre-build step (gitignored, but `strings`-extractable from any build — see `full-review-2026-05-26/04-critique-coach.md:18`).
