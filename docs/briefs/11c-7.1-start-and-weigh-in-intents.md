## Design

### 1. `StartWorkoutIntent` (new file `PhaseTraining/Intents/StartWorkoutIntent.swift`)

- `openAppWhenRun = true`, `isDiscoverable = true`, title "Start today's workout".
- `perform()` calls `StartWorkoutLaunch.shared.request(...)` and returns its line as the dialog.
- `StartWorkoutLaunch` copies `VoiceCheckInLaunch` (`CoachIntents.swift`): `@MainActor final class`,
  `ObservableObject`, `static let shared`, `@Published private(set) var pending`, `consume() -> Bool`.
- `request(snapshot: TodayWidgetSnapshot?, hasActiveWorkout: Bool, now: Date = Date(), calendar: Calendar = .current) -> String`.
  A pure decision, with the snapshot and active flag passed in so tests need no App Group. The intent passes
  `TodayWidgetSnapshot.load(from: UserDefaults(suiteName: TodayWidgetSnapshot.appGroup))` and
  `ActiveWorkoutRegistry.shared.store?.active != nil`. Rules, in order:
  1. Active workout: raise `pending`, say "Resuming your workout."
  2. No snapshot, or no day for `now` in it: raise `pending`, say "Opening Today." (TodayScreen decides whether a template exists.)
  3. Today `.lift` and not `done`: raise `pending`, say "Starting <title>."
  4. Today `.lift` and `done`: do not raise, say "Today's workout is already logged."
  5. `.rest`: do not raise, say "Today is a rest day."
  6. `.sport` or `.event`: do not raise, say "Today is <title>." The app still opens (openAppWhenRun) on Today.
  Every case also sets a second published flag, `showToday` (or have the shell switch tabs whenever the intent
  runs). Pick one, keep it small, and record the choice.
- Expose the line strings as `static let` constants like `VoiceCheckInLaunch` does, so tests compare constants.

### 2. Who consumes the flag

- `RootTabView`: next to the existing `.onReceive(VoiceCheckInLaunch.shared.$pending)`, add one for
  `StartWorkoutLaunch` that sets `tabSelection.selected = .today` on the next main-actor turn (same `Task`
  pattern and comment reason as the voice one). When a workout is already active, `TodayTab` routes to `.log`
  by itself (`enterLiveSessionIfNeeded`), so the shell consumes the flag in that case.
- `TodayScreen`: when `pending` is up, `store.active == nil` and `template != nil`, consume and call the
  existing `startWorkout()`. Check on `.onReceive` of the flag and on `.onChange(of: template != nil)`,
  because on a cold launch the template can arrive after the flag. Do not start from `editableTemplate`
  unless `startWorkout()` already does (it does; call it, do not copy it).
- If the template never appears, the flag stays up harmlessly until the next run. Leave it.

### 3. `LogBodyWeightIntent` (new file `PhaseTraining/Intents/BodyWeightIntent.swift`)

- `openAppWhenRun = false`, title "Log body weight".
  `@Parameter(title: "Weight", requestValueDialog: IntentDialog("What do you weigh?")) var weight: Double`,
  read in the user's display unit (`memory.usesImperial` → lb, else kg). Plain `Double`, like `LogSetIntent`.
- The write must go through the app's live `MemoryStore` instance. A direct UserDefaults write would be
  overwritten by the app's next `save()` of its in-memory copy. Today the store is
  `@StateObject private var memory = MemoryStore()` in `PhaseTrainingApp` with no outside handle. Change
  that to the `sessionStore` pattern in `PhaseTrainingApp.init` (`PhaseTrainingApp.swift` about line 185):
  build it after the wipe and seeds, `_memory = StateObject(wrappedValue:)`, and hand it to a holder the
  intent reads. Put the holder on a small `@MainActor` type in the new file (say
  `BodyWeightIntentActions.store: MemoryStore?`), or add `memory` to `ActiveWorkoutRegistry` beside `store`.
  Choose the smaller diff, record it. Erase All Data resets `memory` in place (`MemoryStore.swift` 143 and
  149), so the handle stays valid.
- `BodyWeightIntentActions.log(weight: Double, in store: MemoryStore?, now: Date = Date()) -> String`:
  - nil store → "Open Phase once, then try again."
  - not onboarded (`store.isOnboarded == false`) → "Finish setup in Phase first."
  - `weight <= 0` or not finite → "Weight must be more than zero."
  - else convert lb to kg with `BodyMetrics` (the sheet's `parseInputAsKg` path shows which helper), call
    `store.update { $0.recordBodyWeight(kg, on: now) }`, and return
    "Logged " + `BodyMetrics.formatWeight(kg:imperial:)`.
  `recordBodyWeight` already replaces a same-day entry, so a repeat is safe.
